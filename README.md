# 全Agent轻量聊天实验台

一个用来验证角色聊天、工具调用和长期记忆的本地实验台。面向任意 SOUL 和任意年龄的用户，使用 Node.js 原生 HTTP、SQLite 与浏览器页面，无第三方 Node 包依赖。

当前为 **`version1.1.0`**，内部应用版本 **1.3.16**，记忆框架版本仍为 **6**；首个公开基线保留在 `version1.0.0`。已接入手动创建、编辑角色：只填写名称与一段完整角色设定，保存后下一轮生效。联网继续提供文字资料。

## 快速启动

需要 Git、Node.js 24 或更新版本，以及可以调用所配置模型的火山方舟 API Key。

```sh
git clone --branch version1.1.0 https://github.com/SuperareLabs/chat-lab.git
cd chat-lab
export ARK_API_KEY="替换为你的方舟_API_Key"
npm start
```

打开 [http://127.0.0.1:4333](http://127.0.0.1:4333)。无需运行 `npm install`。首次启动会初始化 SQLite 和演示用户档案，角色列表为空；点击“创建角色”填写名称与角色设定，再开始聊天。

PowerShell 设置环境变量的方式为：

```powershell
$env:ARK_API_KEY = "替换为你的方舟_API_Key"
npm start
```

不设置 Key 也可以启动页面，但聊天、记忆提取和联网模型调用不可用。模型 ID 与接入点需要在自己的账号下可用；必要时按下表覆盖配置。真实 Key 仅放在本机环境变量或仓库外的凭据文件中，不提交到 Git。

项目默认读取 [config/runtime.env](config/runtime.env)，文件只保存无凭据的运行配置。已有环境变量优先于该文件，例如只开放本机并更换端口：

```sh
CHAT_HOST=127.0.0.1 PORT=4334 npm start
```

默认配置监听 `0.0.0.0:4333`，同一可信局域网可以访问终端打印的地址。**这是可信环境下的实验台，没有完整的公网账号与权限系统。** 仓库公开的是源码，本基线不部署公网服务。

## 页面怎么用

1. 左上角“创建角色”只填写名称、角色设定。角色图鉴可切换角色、编辑原文，或查看后端实际加载的提示词。
2. 右上角创建或选择用户，填写名字、年龄和兴趣；内部 API 的 `childId` 是历史命名，也用于成年用户。
3. 选择会话开始聊天。中间显示消息，左侧查看本轮模型上下文、工具与原始请求，右侧查看概括、记忆和后台整理状态。
4. 开启新会话或停聊满15分钟，会把旧会话交给后台记忆整理。新会话先使用已经保存的资料，不等待整理完成。
5. 查看输入框下方的上下文、累计 token 和预估费用；悬浮或点击可看详情。

部分 SOUL 可声明 `audience.minimumAge`，前后端根据用户填写的年龄限制访问。这是实验用年龄字段检查，不是实名认证。

公开基线不含私人参考音频及默认试听入口，核心文字聊天不依赖音频。`voice` 仍是可选展示配置；需要时自行提供有权使用的本地音频并配置。当前没有实时语音合成或声音克隆功能。

## 模型与环境变量

当前配置将聊天、记忆和联网检索分开，均使用同一个外部 Key：

| 变量 | 用途与默认配置 |
| --- | --- |
| `ARK_API_KEY` | 后端模型凭据，需自行提供。 |
| `ARK_API_KEY_FILE` | 可选仓库外凭据文件的绝对路径；文件需归当前用户所有，权限为0600或0400。 |
| `ARK_BASE_URL` | 默认 `https://ark.cn-beijing.volces.com/api/v3`。更换平台时需自行核对接口兼容性；当前搜索适配器面向方舟。 |
| `ARK_MODEL` / `ARK_ENDPOINT` | 聊天模型／接入点；配置文件为 `deepseek-v4-1-flash-economy-261017`。 |
| `ARK_MEMORY_MODEL` / `ARK_MEMORY_ENDPOINT` | 记忆模型／接入点；配置文件为 `doubao-seed-2-1-lite-260915`。 |
| `ARK_SEARCH_ENABLED` | 配置文件为 `1`；设置为 `0` 可关闭联网工具。 |
| `ARK_SEARCH_ENDPOINT` | 联网检索模型；配置文件为 `doubao-seed-2-0-mini-260428`。 |
| `CHAT_HOST` / `PORT` | 默认 `0.0.0.0` / `4333`；只开放本机时设置 `CHAT_HOST=127.0.0.1`。 |
| `CHAT_DB_PATH` | 本地数据库路径，默认 `data/chat.sqlite`。 |
| `CHAT_TIMEZONE` | 默认 `Asia/Shanghai`。 |
| `CHAT_ALLOW_DATA_RESET` | 配置文件固定为 `0`，不兼容指纹会在删除已有数据前拒绝启动。 |
| `CHAT_CONTEXT_BRIEF` | 默认 `0`，直接使用同次提取维护的有效概括；`1` 仅保留旧派生概括兼容模式，会增加独立模型调用。 |

模型选择不等于调用额度或可用性保证。用量取自服务端实际回执，费用按代码中的价格快照预估，实际扣费以模型服务账单为准。

## 角色创建与编辑

角色只有两个手动配置项：`name`（名称）和 `definition`（完整角色设定）。性格、接话方式、擅长和背景按需要写在同一段原文中，平台不会重新拆分或扩写。可以参考[编写方向](docs/character-prompt-direction.md)、[鳄鱼爸爸](docs/benny-role-setting.md)和[林小满](docs/lin-xiaoman-role-setting.md)的初始设定。

保存内容持久化在 SQLite 的 `agents` 表，页面概览、详情和聊天使用同一份原文。共用工具与记忆规则仍由平台提供。编辑保留原ID、会话与记忆；新建分配独立ID和记忆作用域。保存不打断已在生成的回复，下一轮使用新版本。并行编辑冲突会保留草稿，重新载入当前版本后再保存。

已有数据库首次升级会按原ID导入配置文件中的角色，后续重启以数据库为准，不再用文件覆盖已保存内容。全新数据库不自动创建内置角色。旧松果在首次人工编辑前保留原有渲染，编辑后采用名称＋完整设定。已有头像、受众限制等元数据继续保留，不增加表单字段；角色概览统一展示实际保存的设定。

## 当前机制

- 共用聊天规则与角色设定分开；运行角色以 SQLite 为准，`config/*.soul.v1.json` 仅用于已有数据库的一次性兼容导入和测试夹具。
- 聊天默认带基础资料、当地时间、有效用户概括与本会话消息。具体记忆按需查摘要、读详情。
- 四个工具：`recall_memory`、`get_memory_detail`、`search_web`、`calculate`。模型根据本轮提供的工具与信息缺口决定调用，不强制每轮调用。
- 正常记忆整理只调用一次模型，同时输出新增、补充／更正、提及、撤回及概括。完整结果解析或校验失败时，同一模型最多再定向重整一次；使用原始提取输入追加错误反馈，失败 JSON 只在本地审计。通过严格校验才提交；网络、截断、取消和版本冲突不盲目重试。
- 同一用户与 SOUL 最多500条活跃记忆；按最近实际提及时间归档超量条目。归档仍可搜索，撤回记录退出有效检索；读取不刷新提及时间。
- 同一会话保留最近成功联网结果，供后续轮次复用；失败不覆盖、新成功替换，不跨用户、SOUL或新会话。搜索每轮最多一次，模型回复仍按资料时效判断是否需要重新搜索。

细节见[架构文档](docs/architecture.md)。单次提取质量、召回覆盖和回复篇幅仍受模型与当前实现限制；尤其精确去重命中时新增详情可能未保存，见[已知限制](docs/known-limitations.md)。

## 数据、升级与版本管理

公开仓库不包含私人数据库、备份、聊天记录、真实模型回执或原始本地验证目录。运行时资料保存在自己的 `data/` 目录；测试使用合成资料和独立数据库。

升级前应备份自己的数据库。默认 `CHAT_ALLOW_DATA_RESET=0`，只接纳代码明确列出的兼容指纹；遇到不兼容版本会保留旧数据并拒绝启动。不要用开启重置来绕过升级检查；先确认数据迁移方案，或使用新的独立测试数据库。本基线不因修改提示词而自动清空已有资料。

`version1.0.0` 是首个公开Git基线，`version1.1.0` 接入手动角色创建与编辑。分支名称、内部 `package.json` 的 `1.3.16`、角色修订号、记忆框架版本和数据指纹分别管理。角色内容不再参与平台指纹，普通编辑不会触发数据清空。

## 测试与许可状态

```sh
npm test
```

自动测试使用本地模拟模型和独立数据库，不需要 Key，也不发起真实付费调用。测试通过不代表真实模型提取语义、全历史召回或长会话行为已经稳定。

本基线尚未指定代码许可。第三方资源如有随附许可，按对应说明使用；角色素材和可选本地参考音频的授权范围独立于源码公开状态。
