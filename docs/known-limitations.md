# 已知限制

本文件记录延续至界面分支 `design/motionsites-ui`（应用1.1.1、记忆框架6）的已知边界。手动创建／编辑角色没有改变下列记忆、搜索和模型质量限制，测试通过不替代真实模型质量判断。

## 1. 精确去重命中时，新增详情可能没有保存

**这是已确认、尚未修复的行为。**

后端在 `creates` 中发现与旧记忆规范化摘要相同的候选时，会沿用旧ID，刷新提及及来源后结束该新增分支，没有把候选的新 `detail` 或主题词合并到旧记录。

例如，已有摘要是“用户正在学习游泳”，模型再次输出相同摘要的 `create`，但详情里多了新泳馆。此时条目数量不增加、任务可以成功，新增地点却可能没有进入 `detail`／`detailChanges`。若仍保留本地任务审计，可从原候选和用户原话人工核查；不能仅凭“整理成功”认定新细节完整入库。

这也意味着精确去重是摘要文本级兜底，不是对人物、事项身份、类型和全部详情的完整语义比较。同主题的不同事项仍可能被模型或过泛摘要错误合并，表达不同的重复事实也可能漏去重。

## 2. 召回不是全历史语义搜索

当前 `recall_memory` 使用规范化文字、英文词及中文相邻字匹配，对摘要、主题词、原详情和变化片段评分，再按提及时间等排序，最多返回6条命中。没有向量检索或语义重排。

因此：

- 宽泛查询或同义表达可能漏掉实际存在的记录；工具被调用不等于找全。
- 没有文字重合时，已有事实也可能返回未找到。
- 旧更正片段仍可参与匹配，最终回答需要结合当前摘要和更正理解。
- `fromDate`／`toDate` 筛的是聊到日期，不是事情发生日期。

提取阶段最多500条候选也不等于把全部归档历史参与比较。用户概括受来源选择和1200字符预算影响，不代表完整个人资料。当前“主动查记忆”的提示词提高调用意愿，不改变上述检索覆盖边界。

## 3. 一次提取仍有语义错误边界

正常提取一次模型调用，只有完整输出的解析／校验错误才允许同模型定向重整一次。这一机制能处理结构、来源编号和操作冲突等可检查错误，不能保证事实真实、人物归属、长期／当次分类或语义去重都正确。

模型可能误把提问、局部确认、玩笑、当次情绪或助手补足理解为用户事实，也可能把普通承接误判为对多条旧记忆的实际提及。来源编号合法不代表它确实支持整条记忆。

旧候选默认主要提供摘要，没有完整旧详情。摘要未提到某个细节时，模型不能可靠判断该细节是否已经保存；重复增量、漏更新或误判更正仍可能发生。详情和变化历史不会自动压平成一份完全正确的“当前事实对象”。

## 4. 长会话与输出长度

开放会话的历史文本随对话累积；当前没有自动摘要压缩、滑动窗口或全会话长度预算。停聊15分钟触发整理，不等于连续活跃15分钟就强制结束。

长会话会增加输入token和费用，可能触及供应商上下文限制。每次聊天模型请求输出上限为1400 tokens，记忆提取／重整为8192；达到输出上限会报错，不会通过放宽上限自动重试。结构校验或任务幂等不能解决上下文过长。

“普通单点1–3句、详细按需展开”是提示词软目标。小样本中普通与详细篇幅可以拉开，但未问资料外溢、尾问、限定词丢失和过强归纳仍会出现，不是稳定的回复长度或质量约束。

## 5. 联网与证据时效

搜索由独立模型和联网适配器完成，每轮最多一次；结果数量与摘要长度有限。同一次检索兼顾相关追问，不保证资料全面、实时或权威程度一致。

同会话保留最近一次成功结果供后续复用，但没有独立的事实有效期服务；是否过期、是否要再次搜索仍由聊天模型判断。检索时间、发布时间和事实发生／观测时间不同，模型仍可能丢掉预报、计划或估计限定。

模拟工具结果测试只能证明模型在给定资料下的调用或续答表现，不能证明真实搜索来源新鲜度、真实天气或新闻准确性。公开基线不附带私人运行数据与原始付费评测回执，不应把历史实验结论当作通用准确率。

## 6. 实验台与数据升级边界

当前适合本机或可信局域网，没有完整公网账号、鉴权和生产级租户权限系统。角色 `audience.minimumAge` 依赖填写年龄，是实验限制，不是实名年龄验证。

默认禁止自动重置，未知不兼容指纹会保留旧数据并拒绝启动。升级前需要备份并评估迁移；本基线不提供任意历史版本的通用迁移器。私人数据库、备份、原始会话、凭据和模型回执应保留在自己的受控环境，不作为公开仓库内容。

这些问题在此基线中按现状记录。修复应另开变更、使用独立合成资料验证，避免为了发布源码改动已有用户数据。
