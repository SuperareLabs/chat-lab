# 公共角色库

本功能已合入 `version1.2.0` 维护分支并在线上使用，原 `v1.2.0` 标签仍保留追加前的历史快照。不变更记忆框架或角色提示词组织。角色输入仍为名称与角色设定。浏览器模式中新建角色保存后立即公开，其他已进入实验台的访客可选择聊天。当前服务器配置见[部署说明](deployment.md)。

## 操作与权限

- 新建：创建前在本机保存管理凭证和请求编号，向公共库创建。重试同一请求不会重复创建角色。
- 编辑：公共角色仅创建者可编辑，带当前修订号防止旧编辑覆盖新内容；其他人可以查看设定和聊天。
- 删除：创建者确认后下架公共角色，所有访客同步隐藏；历史聊天、记忆及已存在的后台整理来源不级联删除。已下架ID不能通过旧浏览器快照复活，也不能继续发起新聊天。
- 系统角色：维持原来的本机私人编辑，不能删除。旧版本只在本机创建的角色保持私人，可在本机编辑或删除，不会自动上传公开。
- 排列与默认项：林小满第一、鳄鱼爸爸第二；进入页面默认林小满，默认访客测试资料22岁。

创建者管理凭证由浏览器自动生成，保存在IndexedDB元数据，与发送给聊天模型的工作区快照分开。服务器只存其哈希，修改与删除均由后端校验；共享进入口令本身不提供修改别人的角色的权限。没有新增注册登录流程。清除站点数据或换浏览器会丢失管理凭证，目前没有找回界面。

## 数据位置

| 数据 | 位置 |
| --- | --- |
| 公开角色名称、设定、修订与删除标记 | 独立公共角色SQLite |
| 创建者管理凭证原文 | 创建者浏览器元数据 |
| 管理凭证哈希、幂等创建编号 | 公共角色SQLite，不通过公共API返回 |
| 用户资料、聊天、记忆、用量、私人角色及草稿 | 各浏览器IndexedDB |

`/api/local`仍只在内存里运行访客的工作区。公共角色同步到本机后只把当前聊天角色的设定送入模型，管理凭证不进入快照、提示词或记忆提取输入。用户间不共享聊天与记忆。

## 接口

这些接口与聊天一样受共享入口认证及Host/Origin校验保护。

- `GET /api/catalog`：公开角色列表、删除ID、公共修订号和系统角色ID；带本机管理凭证时返回本机可管理标记。
- `GET /api/catalog?revision=N`：版本相同返回 `unchanged:true`，供轻量同步使用；发生变化才重新同步工作区。
- `POST /api/catalog/agents`：`{name,definition,requestId}`，创建即公开。
- `PATCH /api/catalog/agents/:id`：`{name,definition,revision}`。
- `DELETE /api/catalog/agents/:id`：`{revision}`，下架但保留ID墓碑。

管理请求通过 `X-Chat-Lab-Owner` 发送本机凭证。该字段不发送到模型或写入用户工作区快照。原本工作区的创建/修改接口不能绕过公共角色的权限；本机删除接口只处理本机自建角色。

## 部署与备份

`CHAT_CATALOG_PATH` 默认 `data/public-catalog.sqlite`。正式部署应显式设在代码发布目录外，例如 `/var/lib/chat-lab/public-catalog.sqlite`。目录归运行服务的用户所有；数据库与WAL由该用户写入，不应与旧聊天SQLite共用文件。systemd `ProtectSystem=strict` 下配置 `StateDirectory=chat-lab`，给这个独立目录写入权限，保持代码目录只读。

更新代码或服务器重启要保留公共角色数据库。备份使用SQLite在线备份或停服后复制完整数据库；运行期间不能只复制主文件而遗漏WAL。访客的聊天与记忆仍不在服务器备份中。回滚至不支持公共角色库的旧代码会暂时不展示公共角色，数据库保留供恢复新版。
