# 导师推荐本地试聊

这份原型基于 ChatLab `release1.3.0` 的 `ea6c6d63`。导师会话先判断是否触发 `find_mentor`，当前导师按角色设定和已取得的回执回答。Demo 有十二位导师。布爸的角色正文使用上线版原文，其余角色使用简版设定。 [布爸上线版角色正文](../config/benny-published-prompt.md)

当前实现的规则、接口和转介验收见 [角色推荐与转介](./mentor-handoff.md)。

## 推荐工具怎么判断

孩子主动问知识或求助，或者正在聊超出当前导师专长的内容时，入口执行 `find_mentor`。找导师、接续有效邀请和回应当前推荐卡也走工具。工具模型读取本轮原话、可用名册、有效邀请和推荐记录，决定查目录、留聊、澄清、轻邀或出卡。服务端核对回执结构、导师是否可用，以及回执提到的接受邀请是否对应已展示的邀请。主模型结合回执接话，记忆和计算等工具继续按需调用。 [外层触发](../lib/tool-trigger.mjs) · [内部提示词和回执校验](../lib/mentor-recommendation.mjs) · [本地导师名册](../config/mentor-demo.mjs)

工具回执既决定是否出卡，也约束正文能介绍哪些导师。运行时在发布正文前核对跨导师引导，保留和本轮回执一致的内容。

| 工具状态 | 页面和对话行为 |
| --- | --- |
| `directory` | 回答导师名册或专长问题，引用可用目录。 |
| `stay` | 当前导师接着直接回答。 |
| `invite` | 当前导师给出有用的一步，界面末尾显示一句可接续的具体邀请，无推荐卡。 |
| `offer` | 明确找导师或同意有效邀请时当轮出卡。主动推荐时，当前导师先给简短回答或一步帮助，再出卡。点「找某某」发起转介。 |
| `clarify` | 已明确找导师但方向还宽时，按可用候选介绍具体方向，接一点话题内容，并问一个有助于选方向的问题。 |
| `unavailable` | 导师或相关能力当前不可用时，如实说明。 |

轻邀请只有在实际展示后才可被下一轮接续。服务端核对上一条助手消息的 ID 和已显示的邀请原句。接受邀请时，外层会交给工具处理。孩子拒绝或换话题后，回复成功即结束这次邀请。新需求按当前话题判断。 [会话运行时](../lib/runtime.mjs)

每个回合记录已经展示的推荐时间、原因、导师、目标和卡片状态。工具按孩子和当前角色读取跨会话最近 12 条推荐或轻邀。有历史且模型准备主动出卡或轻邀时，单独复核本次目标与历史记录的关系和孩子的选择。独立新需求可以直接评估。孩子明确找导师或同意有效邀请时，按最新意愿处理。 [回合存储](../lib/store.mjs)

## 启动

使用 Node.js 24 与现有 ChatLab 外部模型配置。Demo 的外层判断使用 Jev，可从环境变量 `OPENROUTER_API_KEY` 或本机 `~/.config/croco-chat-lab/credentials/openrouter.key` 读取凭据，文件权限为 `0600`。从工作树运行以下命令，将占位路径替换为本机模型环境文件。

```sh
PORT=4385 node --env-file=config/runtime.env \
  --env-file=/absolute/path/to/chatlab-model.env scripts/start-mentor-demo.mjs
```

打开 `http://127.0.0.1:4385/`。服务仅在本机监听，使用独立端口、浏览器本地工作区和内存角色库。推荐卡保存在原回复下方。点卡进入目标会话后，目标角色主动发一条欢迎消息。原角色后续收到聊天消息时，可以读取之前转介的私有背景。

`config/runtime.env` 默认开启方舟联网搜索。Jev 在同一次请求里分别判断搜索、导师和计算需求。搜索和导师都命中时，先执行 `search_web`，再把检索线索交给 `find_mentor` 判断专业承接。搜索和计算同时命中时，先获得公开资料，再生成算式交给 `calculate`。主模型结合本轮的工具回执回答。在「模型上下文 → 工具调用」可查看搜索结果和运算回执。

顶部「运行架构」打开 `/architecture.html`。「角色推荐」节点展示外层触发提示、工具内部决策和合成示例。`/tool-trigger-benchmark.html` 展示方舟和 Jev 的同题对照，可展开逐条结果和当前评测规则。

## 验证

```sh
node --test test/mentor-recommendation.test.mjs
npm test
```

自动化测试用模拟模型覆盖界面事件、同轮续答、邀请接续和候选校验。真实模型试聊验证语义判断，分别观察主模型是否查询、工具返回什么状态、目标和界面是否实际生成卡片。

外层实测用 `scripts/benchmark-tool-trigger.mjs`，加载同一外部模型环境后运行，结果写入评测页读取的 JSON。内层可用 `scripts/evaluate-mentor-recommendation.mjs --list` 列出历史用例，使用 `--live` 和 `--case` 复测决策和卡片。内层评测直接进入工具，旧样本的评分对应当时的规则。

## 工具重构后的回归

以下和早期原型小节汇总了历史验证。复测生成的原始记录保存在本机 `verification/` 目录。

- 342 项自动测试通过。真实模型覆盖 48 个场景，包含目录、明确找导师、自身领域或跨领域问答、合理轻邀、目标不明确、不可用导师、改口、拒绝、暂缓和换题。初次测试暴露的「好呀」漏卡通过有效邀请的回调解决。
- 有后续专业卡点的树叶观察和连续纸桥实验都产生了可见的具体邀请，用户同意后才出现对应导师卡。简单的实验步骤仍可能留在当前对话。
- 「找你说的那位」要求最近的可见回复中确实有唯一对应导师，或用户已在当轮点名。缺少依据时先澄清。两个方向以及「好呀」确认的定向复测均通过。

## 早期原型的试测记录

下列报告对应早期由主模型直接选择 `request` 或 `invite` 的实现，用于对照本次工具重构前的表现。

- 全仓 326 项自动测试通过。真实浏览器试过普通问题、明确找小林、点击卡片切到小林的三个步骤。
- 首轮真实模型覆盖 22 个场景和 26 个回合。已有明确意图且目标可用的 7 回合都出正确卡，预期无卡的回合没有误出卡。全口径评分为 18/22 场景，包含轻邀触发和对答措辞的检查。
- 复测中，拒绝继续留在当前对话时直接回答。小林回答了跨领域的冰融化问题且无卡。给定一条清楚的导师邀请，下一轮「好呀」正确出卡。
- 隐式轻邀仍偏保守。树叶和纸桥的项目场景中，模型给了实用步骤，工具没有被调用。使用更强的持续求助样例和较短人设做对照，同样先在当前对话帮助。此行为还需用独立的隐式样例评估覆盖。

| 可试输入 | 预期 |
| --- | --- |
| 分别问布爸和多罗「苹果用英语怎么说？」 | 布爸调用工具后简答。多罗直接回答。两边都不出卡。 |
| 「帮我找小林，我想和他聊聊怎么观察蚂蚁。」 | 当轮出小林卡，当前聊天保持布爸。 |
| 「我想做一份蚂蚁观察报告，已经观察三天了。」 | 先给可继续做的建议。若要请小林给具体指导，先只轻邀。 |
| 上一句问「要不要找小林帮你设计记录表？」后答「好呀」 | 当轮出小林卡。 |
| 上一句问「要不要先记录蚂蚁搬什么？」后答「好呀」 | 接着讲观察方法，无卡。 |
| 「我朋友说要找莫非，这句话什么意思？」 | 按语境解释，无卡。 |
