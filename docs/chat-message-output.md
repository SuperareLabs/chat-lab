# 消息与段落分离：本地 ChatLab 验证记录

日期：2026-11-17。模型：deepseek-v4-1-flash-economy-261017，思考关闭。

## 现在如何工作

模型正文返回 `{"messages":["第一条消息","第二条消息第一段。\n\n第二条消息第二段。"]}`。每个数组项是一条消息；单换行、空行、列表、代码块都留在项内。前端不根据换行、长度或段落数量猜气泡数。

消息数组从模型解析后，经 SSE reply_part、parts 存储、历史读取和请求重放原样传递。送回模型的 assistant 历史也保留消息数组。记忆提取仍使用正常对话文字，不拿协议 JSON 当用户事实。

日常规则继续是默认 1 条、需要才 2～3 条，每条通常 5～20 字、最多 30 字；没有靠截断或强行拆句达标。明确要求详细讲解、步骤、长文或代码时允许展开，通常在一条消息内分段；日常的 3 条限制不被错误地套在详细内容上。解析器的 32 项上限只用于防御异常响应，与日常话量规则不同。

## 格式异常如何处理

当前接入使用供应商 JSON Object 模式，并在本地检查对象字段、数组与每项类型。此模式不能被当成严格 Schema 保证：实测用户明确要求破坏 JSON 格式时，模型可能返回空白。

最终正文格式不合规时，只用原始输入与已有工具结果修正一次，不把失败内容塞回模型，不重复执行工具；两次模型调用都保留用量记录。网络错误、超时、模型长度截断不自动重试。修正后仍不合规则明确报错，保留用户消息，不把半截 JSON 显示成气泡。

旧的纯文本供应商输出按一条消息兼容，不按换行猜测。明显残缺或错误的消息 JSON 不走这个兼容出口。已有历史内容和资料不重写；旧回复没有明确 parts 的，显示为一条消息。

## 验证结果

- 最终版本真实模型：44 / 44 场景完成。43 / 44 场景直接合规；1 个格式干扰场景通过一次修正完成。
- 最终版本共 51 次真实模型调用（包含工具续答与一次格式修正），所有请求 thinking=disabled、无 reasoning_effort。
- 覆盖四个现有角色；招呼、叫名字、乱码、追问、打趣、接价码、喜讯、倾诉、告别、AI/App入口、明确一条多段、世界观、步骤、代码、表格、JSON字符转义、大整数、小数、除零、记忆无结果、工具续聊和连续三轮。
- 搜索续聊使用明确的合成搜索结果，只验证调用与续答链路，没有把它当成真实地点事实查询。
- 隔离浏览器验收通过：2 项 messages 显示 2 气泡；1 项内含多段和多行代码显示 1 气泡；刷新后结果一致，未出现 JSON 外壳。测试标签已关闭、临时测试服已停止。
- 33 个日常样本消息数最多 3 条，单条最长 17 字；44 个场景的整轮中位耗时约 1.44 秒（有限样本，不作延迟保证）。
- 318 项程序测试通过：含数组持久化和重放、历史兼容、工具前后消息、格式修正仅一次、不重复工具、截断与坏格式不泄露、原输入保留，以及聊天与记忆隔离。
- 大整数截图题结果：210380192 × 2791387 = 587252533006304。

这些是有限样本结果，不代表未来每轮百分之百成功。单次格式修正会增加一轮模型等待与费用，正常回复不额外调用。
